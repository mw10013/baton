### 1.1 What legacy does

**Dashboard** (`/admin`). `s-page` "Admin v`<version>`", Sign out as the secondary action, then one section per console: heading, one sentence, a primary "View …" button. Shops: "View connected shops and their stored Shopify sessions." / View shops.

**Shops** (`/admin/shops`). `s-page` "Shops", `inlineSize="large"`, breadcrumb Admin. One `s-table` in an `IndexSection` labelled "Shops table", paginated when there is a page either way, a search field "Search by shop" in the filters slot (it writes `filter` to the URL on change and clears the cursors). Columns: Shop (a link to the shop page), Shop Agent ID, Shop GID, Scope, Access token expires, Refresh token expires, Plan (`PlanCache`), Plan expires, Access token and Refresh token (`Present` success badge or `Missing` critical). An empty page shows an info banner "No sessions."

**Shop page** (`/admin/shop/$shop`). `s-page` with the shop as heading, breadcrumb Shops.

- `NotFound`: a warning banner "No session", "No stored session for this shop. Uninstall deletes the row, so the app is not installed here."
- `Found`: a critical banner with Refresh plan's error, if any; then a **Plan** section (`Things` of `Tiles` of fields, then Refresh plan with "Asks Shopify for the current app subscription and rewrites the cache. Use it when a merchant reports a subscription change that has not taken effect."). Fields: Cached plan (`PlanCache`), Fresh until, Orders this billing cycle ("N of M", M "—" when the cache grants nothing), Billing cycle ("start – end" or "– open"), Plan boundary, Usage events pending, Orders limited, Members ("N of M"), Members high-water, Database size (one decimal MB), Open orders ("N of 2,500"), Last retention sweep. Then a **Shopify session** section: Shop GID, Scope, Shop Agent ID, Shop Agent ID from name (`Matches` or `Mismatch` with the derived id), Access token expires, Refresh token expires, Access token, Refresh token.
- A field is a label (`s-text tone="neutral"`) over a `Token` value, "—" when empty.

**`PlanCache`**: a badge per `AdminShopPlanCache` state (Subscribed: success, the plan; Unsubscribed: warning; Stale and Never fetched: neutral; Unrecognized: critical) beside the stored handle verbatim, "the one surface that can say which handle it was".

**Rules legacy states in JSDoc** that carry over: tokens never leave D1 (projection in SQL, not a field dropped afterwards); the cursor clause is present only when a cursor is, so a page reads `limit + 1` rows; `%` and `_` in the filter are accepted wildcards for an internal search; the row is checked before the actor is touched; the plan is decoded, never resolved, so viewing never mutates; Refresh plan is the only write; `blocking` reloads, because every number is a point-in-time reading whose purpose is to be current.

### 1.4 Risks

- **A token reaching the browser.** The shop page and the list are serialized to the browser. `ShopSessionRepository.find` reads `select *`; using it here would ship live offline tokens. The redacted reads project in SQL, and a unit title pins it (§4).
- **An empty actor per typo.** `getByName` creates the object. The row check must come first, as legacy's; a unit title pins "no actor call for a shop with no row".
- **Refresh plan has side effects on a live shop.** A changed handle closes every merchant and member socket of that shop (`3401`) and may move its billing cycle. That is the intent (an admin correcting a cache that disagrees with Shopify), but the button must stay a deliberate POST, never reached by a loader or a preload.
- **Destroy empties a shop's work for good.** `destroyOrphan` must refuse any name with a `ShopSession` row, checked in the Backend at the press, not only in the list the page rendered (Q13).
- **The inventory token is a standing credential.** Hand-made, bound on staging only, `Redacted` (Q13).
- **Admin e2e shares the e2e store.** Refresh plan in the default suite would revoke the sockets of every parallel embedded spec on `mw10013-e2e-shop-00` whenever the handle changed. The default suite stays read-only, as legacy's spec says; Refresh plan runs only in the headed billing project (Q12).

## 5. Questions and recommendations

1. **Where does it run?** Nothing else is in flight. **Recommendation:** one implementation thread on `main` through `implement-plan`, the three sub-slices in order, no `CHECKPOINT` (no spike, no human step until the staging check).

2. **Is the console still not live?** Legacy kept it point-in-time on purpose. Here an admin has no socket (the gate admits a merchant or a member of the shop, and an admin is neither). **Recommendation:** as legacy: loader-only, no procedure, no socket.

3. **The dashboard.** Legacy's has "Admin v`<version>`" and three consoles as heading, sentence and primary "View …" button. This repo's has "Admin", "Signed in as …" and a Members section with a link, a page legacy does not have. **Recommendation:** add Shops first in legacy's shape (heading "Shops", "View connected shops and their stored Shopify sessions.", primary button View shops); keep Members (it is this repo's and `members.spec.ts` uses it) and give it the same shape (View members); keep the heading "Admin" (this repo has no app version; adding one for a heading is out of scope).

4. **One schema for the `ShopSession` row (revised after review round 1: a design flaw, not a field to add).** One D1 table has two schemas, and the shop key has two brands:

   | Concept       | Live copy (imported)                                                                                                        | Dead copy (imported by nothing)                                                                                                                                    |
   | ------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
   | The row       | `ShopSessionRow` (`src/backend/shop-session-repository.ts`): `ShopKey`, `shopActorId`, `refreshLeaseUntil`, plain `shopGid` | `ShopSession` (`src/domain/platform.ts`): legacy's, `Shop`, `ShopGid` branded, no actor id, no lease; it carries legacy's field JSDoc                              |
   | Auth's insert | `ShopSessionUpsert` (repository; omits the lease and plan columns), used by `shopify.ts`                                    | `ShopSessionUpsert` (domain; omits the plan columns only)                                                                                                          |
   | Redacted      | —                                                                                                                           | `ShopSessionRedacted`, `ShopSessionRedactedPage` (domain; only `adminShopPlanCache`'s parameter type names the first)                                              |
   | The shop key  | `ShopKey` (`src/contract/shop.ts`, the myshopify pattern; the glossary's word), in 39 files                                 | `Shop` (domain, any non-empty string), used by three schemas in `shop-work.ts`; its JSDoc says "Duplicates the contract's `ShopKey` until this one's callers move" |

   **How it happened.** The embedded admin work (2f352e7, 2026-10-14) wrote the row schema into the Backend, before `src/domain/` existed. The domain port (223ce67, 2026-10-17) copied legacy's `Platform.ts` whole, as roadmap Q3 said, and nothing reconciled the copies with what the Backend already owned. Nothing imported the domain's, so nothing failed. The same verbatim copy left more of legacy's platform dialect that this repo replaced and nothing references: `AuthSession`, `LoginInput`, `UserId`, `UserRole`, `SessionId`, `SocketKeepalivePing`, `SocketKeepalivePong`, `InvalidatedMessage`, `RevokeMemberConnectionsInput` and the `CONNECTION_*` header names (Better Auth's session, `Notice`, Effect RPC's pings and the gate header replaced them); `userIsAdmin` is referenced only by its test.

   **Recommendation:** one schema per concept, in the domain, as legacy had it, as H's first step (a refactor: no table change, no reset):

13. **The actor inventory and orphan pages (revised after review round 1: orphans matter and are hard to manage, so both pages port; this supersedes roadmap Q10's skip and its §5 row).** An orphan is an actor with stored data and no `ShopSession` row. Here one appears when uninstall's `destroy` fails (logged and dropped), when D1 is reset without the actors (`vp run db:reset`), or when a write reaches an actor after its row went. Legacy found them by listing every object of its namespace with Cloudflare's REST API, anti-joining the ids against `ShopSession.shopAgentId`, and destroying by id. **Recommendation:** port **Shop actors** (`/admin/shop-actors`, legacy's Shop Agent Objects) and **Orphan shop actors** (`/admin/orphan-shop-actors`) with legacy's tables, banners, paging, and its tombstone rule (an object with `hasStoredData: false` is listed without Destroy, since destroying it re-creates it), the word agent becoming actor (glossary). What differs, each for a reason:
    - **The inventory call.** Legacy hand-wrote an `HttpClient` against `list_objects` and found its namespace by class and script name. Here the Backend calls distilled's typed `listNamespaceObjects` (`@distilled.cloud/cloudflare`, `durable_objects`), with the namespace id from Alchemy's `ShopActor` resource (`namespaceId`, an output bound at deploy), so there is no lookup.
    - **The token** (settled in chat): `CLOUDFLARE_WORKERS_API_TOKEN`, already in `.env` and `.env.staging`, reaches staging through the stage config record (a new `StageConfigValues` field, the runbook's "Add a value"), as the Partner token did (billing Q7). An Alchemy `AccountApiToken` is not used: the OAuth login has no API-token scope, and Workers Builds' deploy token is not known to have one. It is bound on staging only (production when it exists): local stages have no cloud inventory.
    - **The orphan join.** By name, not id: every actor here is created by `getByName(shopActorId)`, so the inventory names it. `ShopSessionRepository.findOrphanShopActorIds(names)` ports legacy's `json_each` anti-join on `shopActorId`.

Here `BackendApi.destroyOrphan({ name })` refuses a name that has a `ShopSession` row, then calls `ShopActors.destroy(name)`. A forged name can at worst create and empty an object, which leaves a harmless tombstone. If the spike finds unnamed objects, patch Alchemy's binding to expose `idFromString` and `get` (`pnpm patch`) and destroy by id as legacy did.
    - **Local stages.** Legacy's dev read miniflare's local explorer; Alchemy's local workerd has none. On a stage without the token both pages show an info banner, "The actor inventory is Cloudflare's, so it is not available on this stage.", and the dashboard still links them.
