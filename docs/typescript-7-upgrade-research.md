# TypeScript 7 upgrade — research

Research date: 2026-09-09. Scope, as agreed: blockers, breaking changes, and required actions for upgrading to stable `typescript@7.0.2`. Includes a scratch trial (no repo files changed). Not a full runbook.

## Verdict: go, low risk

No hard blocker found. The project is already shaped like a TS 7 project: both tsconfigs conform to the TS 7 hard rules, and the scratch trial type-checks clean (`tsc -b . test` under 7.0.2, exit 0). The one risk area is lint (`@tanstack/*` ESLint plugins loaded as oxlint `jsPlugins`), and evidence says it keeps working — details in §4. Expected cost: one dependency bump plus a verify pass, not a migration.

## 1. What TypeScript 7 is

- `latest` on npm is `7.0.2` (verified against the live registry; `next` is `7.1.0-dev`). TS 7 is the Go port ("Corsa"), ~10x faster; type-checking semantics are deliberately identical to 6.0.
- The headline breakage is twofold: (a) options deprecated in 5.x/6.0 are now **hard errors**, and (b) **7.0 ships no programmatic Compiler API** — `require("typescript")` returns only `{ version, versionMajorMinor }` (proven in trial, §3). The new API lands in 7.1.
- Microsoft's own rule, confirmed by trial: anything clean on 6.0 (no `ignoreDeprecations`) compiles identically on 7.0.

## 2. tsconfig audit — already compliant

`tsconfig.json` and `test/tsconfig.json` (the only two configs) violate none of the removed options:

| Removed / changed in 7.0                                  | This repo                                                                                                                                                                  |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseUrl`                                                 | Absent (`paths` is already root-relative: `"@/*": ["./src/*]"`, `tsconfig.json:30-32`)                                                                                     |
| `target: es5`, `downlevelIteration`                       | `ES2025` / `ES2023`, `tsconfig.json:5`, `test/tsconfig.json:24`                                                                                                            |
| `moduleResolution: node/node10/classic`                   | `bundler` in both                                                                                                                                                          |
| `module: amd/umd/systemjs/none`                           | `esnext` in both                                                                                                                                                           |
| `esModuleInterop` / `allowSyntheticDefaultImports: false` | Neither set (defaults apply)                                                                                                                                               |
| `alwaysStrict: false`                                     | Not set                                                                                                                                                                    |
| `module` keyword in namespace decls                       | Only `namespace JSX` (`src/lib/shopifyAppBridgeElements.ts:16`) and `namespace Cloudflare` (`test/env.d.ts:4`) — `namespace` is still legal, only `module` was banned      |
| `assert` on imports                                       | Already `with { type: "json" }` (`vite.config.ts:9`)                                                                                                                       |
| `ignoreDeprecations`, `///` directives                    | None anywhere                                                                                                                                                              |
| `types` default `[]` (was "all `@types`")                 | Both configs list `types` explicitly, so the default change is inert                                                                                                       |
| `rootDir` default `./`                                    | Root config sets no `rootDir` and includes the whole tree — consistent with the new default. Test config uses `rootDirs` (plural, unrelated) — trial passed, so no action. |
| `strict`, `noUncheckedSideEffectImports` defaults         | Already explicitly `true`                                                                                                                                                  |

No `.js` sources with JSDoc types (the JS-support regressions don't apply), no `infer Head/Tail`-style template-literal metaprogramming, no decorator emit (`experimentalDecorators` unset; decorators are Babel-transformed for Vite only). The single consumer of `tsc` is `package.json:35` (`tsc -b . test`); `-b` takes project paths, not file args, so the new `--ignoreConfig` rule for bare file args doesn't bite.

Minor smell, not a blocker: root `types` lists `"./worker-configuration.d.ts"` (`tsconfig.json:10`), which is a file path in a package-name slot. Harmless today (the file is also covered by `include: **/*.d.ts`) and the TS 7 trial passed with it in place — leave it.

## 3. Scratch trial results (2026-09-09, no repo files touched)

All run from a scratch dir under the pre-approved temp area plus read-only `npx` runs in the repo. Only side effect: `node_modules/.tmp/*.tsbuildinfo` rewritten in 7.0.2 format (gitignored cache; a TS 6 run rebuilds it).

1. **Binary runs**: `npx -y typescript@7.0.2 --version` → `Version 7.0.2` (darwin-arm64 OK).
2. **Type-check passes**: `npx -y typescript@7.0.2 -b . test --verbose` → both projects rebuilt (expected version-churn rebuild), **exit 0, zero errors**. This is the strongest signal: the entire `src/` + `test/` tree is clean under the real 7.0.2 checker.
3. **Install resolves**: a scratch `package.json` with `typescript@7.0.2` + the lint toolchain, `pnpm install --lockfile-only` → **exit 0**. Only peer warnings (below). Note: this repo uses pnpm, which warns on unmet peers; npm hard-fails the same tree, so don't switch package managers mid-upgrade.
4. **No-API proof**: `require("typescript")` on 7.0.2 exposes exactly 2 keys (`version`, `versionMajorMinor`) — no `createProgram`, no `SyntaxKind`.
5. **API-consumer crash proof**: loading `@typescript-eslint/typescript-estree@8.70.0` against TS 7.0.2 throws `Cannot read properties of undefined (reading 'Cjs')`. Relevant because the TanStack plugins sit on that stack — see §4 for why it doesn't bite.

## 5. Required actions

1. Bump: `pnpm add -D typescript@7.0.2` (exact pin, matching the repo's current style — no `^`, so no surprise major moves later). Keep `oxlint-tsgolint@7` in step with the TS version per its versioning scheme.
2. `pnpm install` — expect the `@typescript-eslint/*` unmet-peer warnings from §4; benign.
3. Verify, in order: `pnpm typecheck` → `pnpm lint` → `pnpm test` → `pnpm build` → `pnpm graphql-codegen`. The trial predicts all green; `lint` is the one to watch (see §4 fallback).
4. Optional follow-ups, not required: try `oxlint --type-aware --type-check` as a future single-pass replacement for `tsc --noEmit`; experiment with `--checkers`/`--builders` on CI runners only after a baseline is recorded.
5. Rollback is one commit: `git checkout package.json pnpm-lock.yaml && pnpm install`. No code, config, or schema changes are part of this upgrade, so there is nothing else to unwind. Do **not** add `@typescript/typescript6` — nothing in the build path needs the legacy API.
6. 7.1 outlook: the new programmatic API is expected there. Nothing in this repo needs it, so 7.1 will be a routine bump when it lands; the `@tanstack/*` plugin peer warnings should resolve as `typescript-eslint` adopts it.
